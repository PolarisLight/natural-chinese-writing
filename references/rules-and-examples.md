# 完整规则与例句

此文件是 natural-chinese-writing 的完整白名单与使用参照。例句均为说明规则而自拟，覆盖研究论文、软件系统、工程操作、项目报告和一般表达；其中数字及事件不指向真实研究或项目，也不向待改稿提供事实。以当前用户指令、核心规则、信息守恒与最小修改为准。

## 核心规则

| 编号 | 规则 | 原文 | 审校结果 |
| --- | --- | --- | --- |
| P01 | 合并同主体的重复句架，保持每个动作与对象的一一对应 | 系统记录错误，便于后续排查。系统归档日志，便于后续排查。 | 系统记录错误，并归档日志，便于后续排查。 |
| P02 | 先说明工具的功能，再交代使用状态；也可拆成两句 | 能够帮助研究人员按实验条件检索已有数据的分析工具已完成部署。 | 分析工具能够帮助研究人员按实验条件检索已有数据，现已完成部署。 |
| P03 | 自然、有作用的“当……时”保留；较长条件使行动主体出现过晚时，按S01调整语序并保留条件关系 | 当编写代码的成本趋近于零时，走错技术方向的代价就变高了。 | 当编写代码的成本趋近于零时，走错技术方向的代价就变高了。 |
| P04 | 自然、有作用的话题引入保留 | 对于维护人员来说，定位间歇性故障最费时间。 | 对于维护人员来说，定位间歇性故障最费时间。 |
| P05 | 保留合理的前后连接词；无上下文证据时不删句首路标 | 此外，成本也是需要考虑的因素。 | 此外，成本也是需要考虑的因素。 |
| P06 | 连续动作需要衔接，保留已有的时间推进 | 测试开始前，工程师检查设备。测试进行中，工程师记录温度。测试结束后，工程师导出数据。 | 工程师在测试开始前检查设备，随后在测试中记录温度，测试结束后再导出数据。 |
| P07 | 三项并列补足末项连接；动宾短语可用“并／以及”消歧，不机械套用“和” | 新流程有助于减少重复录入，缩短审核时间，提高记录完整性。 | 新流程有助于减少重复录入，缩短审核时间，并提高记录完整性。 |
| P08 | 连续并列的末项用“和／或／以及”连接；保留原有关系 | 服务支持文件上传、权限管理、日志导出。 | 服务支持文件上传、权限管理和日志导出。 |
| P09 | 句间关系已有依据而衔接不清时，补常用连接词 | 工程师检查接口。工程师要检查权限。 | 工程师检查接口，同时也要检查权限。 |
| P10 | 点明上下文已有的行动主体，不猜责任人 | 开发者负责修复故障。通过反复测试，完成了修复。 | 开发者负责修复故障。开发者通过反复测试完成了修复。 |
| P11 | 按语义联系组织句子；紧密相关的内容保持连贯，不因分句各自完整就拆句，保留原段落 | 接口测试用于检查接口行为，一次测试包含请求发送和响应核验。 | 接口测试用于检查接口行为，一次测试包含请求发送和响应核验。 |
| P12 | 清理无独立作用的同义并列，保留实质内容 | 团队需要明确预算上限、最高预算额度和预算的最高额度。 | 团队需要明确预算上限。 |
| P13 | 明示数量的清单保留全部项目，末项补连接 | 报告检查五项：版本号、构建时间、依赖版本、运行平台、错误日志。 | 报告检查五项：版本号、构建时间、依赖版本、运行平台和错误日志。 |
| P14 | 不同主体分工被顿号压在同一句时，可拆句 | 开发者、测试人员、维护人员分别负责功能实现、验收测试、上线维护。 | 开发者负责功能实现。测试人员负责验收测试，维护人员负责上线维护。 |

P01 合并前逐项核对主语、动作和对象。同一主体也可能执行不同的动作，不能把“记录错误、归档日志”改成“记录和归档错误和日志”。保留各自的动宾短语：“系统记录错误，并归档日志”。不同主体或明确分工继续分别表述。例如“工程师检查传感器。实验员保存测量记录。”不能合并成两人共同完成全部动作。

P02 只调整已有功能与状态的说明顺序，不为无状态信息的原文增加“已投入使用”。原文写“计划试用”时，继续表达计划。

P03—P05 保护实际的时间、条件、范围和衔接作用，与P09共同执行。可以补出原本隐含且明确的关系，也可以保留“同时”“此外”“因此”等自然承接。不能只因句首有路标就删词；“因此”“从而”“最终”等需要已有因果或先后依据。“不仅……还……”“除了……还……”只呈现原有补充、递进或分类，不把并列改成更强判断。套壳能否删除有疑问时，保持原文。

P06 的“随后”“再”对应原文的测试开始前、进行中和结束后。只表达并列的动作不擅自补成先后关系。

P07—P08、P12—P14共同处理并列：先判断项目是否有独立作用，再决定保留、拆句或去重。检查主体，也检查宾语、动作、能力和条件；不能仅按词性或顿号数量机械处理。末项前按原意用“和／或／以及”，如“本地文件、共享目录或远程地址”表示选择。名词并列可用“和”；三个动宾短语并列时，应保留每个完整短语，末项可用“并”或“以及”避免误读。“和”并非只能连接名词，是否改写取决于具体歧义。

明确写出“五项”“三个因素”等数量的清单，以及法规、配置、科目、步骤和不同责任主体，要完整保留；不为减少顿号删掉独立的评价维度、能力或工作环节。没有明示数量也不能自动删项。只有同义重复、上下文已经完整覆盖且无独立作用的内容才可删并；拿不准时保留并改用句子呈现。直接引语、法条原文、固定名称和机器字段不改标点。

P09—P11允许补连接、点明主语及按完整意思安排标点。紧密相关的功能、解释、条件、经过或结果可以共同组成一个句子，不把每个完整分句分别截成短句。主语必须能从原文确定；不能从外部知识推断人物、机构或责任归属。段落数量仍按A05执行。补出“流程”“问题”等中心词必须有明确对应，不能添加“核心”“关键”等评价。必要的“的”“了”“能够”等词可以保留或补足语法，不为了压字数制造生硬表达。

## 明确的语言改写规则

| 编号 | 规则与触发条件 | 原文 | 审校结果 |
| --- | --- | --- | --- |
| L01 | 通常先给核心判断，再紧凑保留原因排除或概念对照；强调顺序服从上下文 | 问题不在于缓存容量，而在于失效策略。 | 问题出在失效策略，而不是缓存容量。 |
| L02 | 禁用无信息起手式：“说白了”“说穿了”“先说结论” | 先说结论，这个方案成本太高。 | 这个方案成本太高。 |
| L03 | 相邻两句以上句式雷同，且造成无谓复述或机械铺陈时，在原段落内调整；清楚的对照、分类与分工表达保留 | 研究团队保存原始数据，便于复核实验。研究团队公开分析脚本，便于复核实验。 | 研究团队保存原始数据，并公开分析脚本，便于复核实验。 |
| L04 | 同一段平级案例重复说明同一件事；保留各案例信息，调整主次或合并表达 | 数据集甲采用人工标注。数据集乙采用人工标注。数据集丙采用规则标注。 | 数据集甲和数据集乙采用人工标注，数据集丙采用规则标注。 |
| L05 | 揭晓式破折号或没有必要的插入；不用它强调普通判断 | 下一轮要解决一个问题——接口超时。 | 下一轮要解决接口超时的问题。 |
| L06 | 冒号前为无信息提示语；提示语承担衔接时保留其信息 | 一句话总结：这个方案成本太高。 | 这个方案成本太高。 |
| L07 | 上下文已明确清单性质，一行只宣布下方有列表；只删宣布句，不删项目 | 所需设备：<br>设备清单如下：<br>• 温度计<br>• 记录仪 | 所需设备：<br>• 温度计<br>• 记录仪 |
| L08 | 连续三个以上小标题用“一、二、三”或“第一、第二”编号，且编号无步骤、时间或指代功能；仅去编号 | `## 一、系统概况`<br>`## 二、运行记录`<br>`## 三、维护建议` | `## 系统概况`<br>`## 运行记录`<br>`## 维护建议` |
| L09 | 理想化职业人格比喻：“像/相当于一位/一个职业角色”，带褒义修饰或升级式展开，且未增加机制解释 | 这个系统像一位智慧顾问，能检查配置文件。 | 这个系统能检查配置文件。 |
| L10 | 泛泛概括重复覆盖同段或相邻段已有的具体值、时间或对象；仅用已有材料 | 处理效率明显改善。耗时从两小时缩短到四十分钟。 | 耗时从两小时缩短到四十分钟。 |
| L11 | 动作表达结合语境判断；自然的“完成了对……的……”保留，不按形式强换动词，保住完成状态 | 团队完成了对流程的优化。 | 团队完成了对流程的优化。 |
| L12 | 过长前置定语：中心名词前修饰超过十五字，或同一前置修饰链中两个及以上“的”字嵌套连用，读到句中需要回头确认；在原段内拆分，保留含义与说明顺序 | 能够帮助研究人员按实验条件检索已有数据的分析工具已完成部署。 | 分析工具能够帮助研究人员按实验条件检索已有数据，现已完成部署。 |
| L13 | 核对所属关系的层次；归属能明确理解时保留原句，不因“的”字连用自动改写 | 团队完成了对系统的配置的检查。 | 团队完成了对系统的配置的检查。 |
| L14 | 名词前“一个/一种”与另一数量或指示表达语法重复；数量承载信息时不动 | 我们需要一个关于权限管理的一套新方案。 | 我们需要一套关于权限管理的新方案。 |
| L15 | “这意味着”“这说明”“换句话说”等仅同义复述上句；有新推论时保留 | 系统会自动保存日志。这意味着日志会自动保存。 | 系统会自动保存日志。 |
| L16 | 非首段以评论语开头，整句没有“这/那/其/此”等回指；补回指词或明确已有对象 | 听起来可行，可以安排压力测试。 | 这听起来可行，可以安排压力测试。 |

L01 先区分无信息的修辞铺垫与有实质作用的对照。无信息的铺垫可删；真实的原因排除、样本排除、禁止事项或方法差异须等义保留。通常先说重点，再把排除项或对照项紧接其后，例如“问题出在失效策略，而不是缓存容量”。对照部分保持紧凑，句子重心落在核心判断。若前文持续讨论缓存容量，当前句承担纠正或转折作用，可保留“问题不在于缓存容量，而在于失效策略”等符合承接需要的顺序。强调顺序和句子轻重依据上下文判断，不按否定词或固定句式机械改写。

L03—L04 不处理原本应整齐的操作步骤、并列条款、对话、引语或文学性排比；成组对照、分类与分工也可以使用相同句架。例如“方法A的准确率为89%，平均延迟为60毫秒。方法B的准确率为90%，平均延迟为100毫秒。”原样保留，便于读者比较。叙事中的经过、处理和结果承担不同功能时保留。合句后复查 P01、P06 与 P07，不能停留在机械串联。

L05 服从已有作者风格；不按固定频次清除全部破折号。L06—L07 不处理人物直接引语、标题、列表内部的规范冒号、网址、代码及机器字段；保留真正承担总分说明的冒号。

L08 不处理 Markdown 有序列表、只有一两个编号的小标题，以及“见第三条”这类指代所需编号。L09 保留普通比喻、具体人物喻体、具有解释作用的比喻及符合文学语体的表达。

L10 原文没有具体材料时不编数字，不因为抽象而删句；L11 不按动词包装的外形自动改写，自然的“完成了对……的……”原样保留。“完成”交代工作已经结束时，其状态信息也须保留。L12—L14 保留专业术语、固定译法、法律或公文固定表达；信息只能在原段内等义调整。

L16 不处理首段、已有回指的句子、对话或引语内部；不以缺回指为由删除独立比喻。起手式与回指规则重叠时，直接清理已命中的起手式，不为保留套话而硬补主体。

## 主干延迟与全文累积

| 编号 | 规则 | 原文 | 审校结果 |
| --- | --- | --- | --- |
| S01 | 主语被较长背景、条件或前置从句推迟时，先明确主体，再连贯交代条件与行动，保留时间关系 | 在完成两轮测试、汇总故障日志并与维护人员讨论之后，团队调整了部署方案。 | 团队在完成两轮测试、汇总故障日志并与维护人员讨论后，调整了部署方案。 |
| S02 | 名词前多层修饰集中；先给中心名词，再陈述已有属性 | 这些内容完整、结构清楚且便于检索的技术文档已经整理完成。 | 这些技术文档已经整理完成，内容完整、结构清楚，也便于检索。 |
| S03 | 主语与主要动作之间夹多层框架表达；缩短距离，保留判断依据 | 工程师在结合故障日志并充分考虑服务器容量与维护时间安排的基础上，对部署方案进行了调整。 | 工程师结合故障日志，充分考虑服务器容量与维护时间安排，调整了部署方案。 |
| S04 | 检查同类结构是否贯穿连续句段；结合相邻句与动作衔接规则处理 | 项目启动前，负责人核对需求。项目执行中，负责人记录进度。项目结束后，负责人汇总结果。 | 负责人在项目启动前核对需求，随后在执行中记录进度，项目结束后再汇总结果。 |

普通“形容词+名词”、必要的条件前置、自然长句、文学性倒装保留。要检查读者是否能及时识别“谁/什么、做什么、发生什么”，也要看中心名词和主要谓语的位置。不要强制全部句子以主语开头。较长背景或条件使行动主体出现过晚时，优先提前明确主体，再将条件与行动连贯组织在同一句中。

报告“大量存在”时，交代实际检查范围、位置和代表性例句；未计数不编比例或密度。没有全文时，仅说明已提供段落的现象。S01—S04 不授权新增主体、改变条件的约束对象，或以“读起来更顺”为理由全面改写。

先判断防御性句子的功能：无信息免责声明、必要范围、真实方法局限、有效概念区分、证据限定或重复澄清。只删冗余，不以“更有力”为由删条件或增加“显著”“全面领先”。证据是否支持某种解释，与该解释中的关系是否成立，可以分别具有不确定性；只合并同一层的重复保留词，不把两层限定当成赘词。

“只能提供有限参考”等表达如果承载作者对适用范围或用途的判断，就应保留。没有上下文依据时，不直接归为无信息谦辞。指标变化之外的独立评价同样需要保留并按需核验；不能仅凭两项指标自动删除作者结论。缩小或撤回实质主张，须有明确证据及相应内容审查授权。

真实限定通常在方法、讨论或局限部分集中说明；当前句省略限定会误导时继续保留。跨段搬移、合并段落或重排章节须在相应任务获得授权，不能借集中限定自动重构全文。

每项实验的作用可审查为方法是否有效、优势来源、排除替代解释、适用条件。保留影响核心结论的不利结果；重复展示、离题材料或补做实验可以提出建议，不自动删研究内容。

## 最终验收

- 每处改动能对应A/P/L/S/D/T/K/C中的明确允许项；仅检查项不构成自动修改授权。
- 未命中句子逐字保留，其他改动限于解决触发问题。
- 实质信息、引文、归属、限定和判断强度完整；合并动作后未改变主体与对象关系。
- 框架、层级、材料位置及其余段落顺序数量保持；变更仅限明确规则或用户另行授权。
- 功能与状态顺序清楚；时间、条件、范围和衔接未被抹去。
- 动作推进有自然连接；已有因果、转折、补充、举例或递进关系表达清楚，未新建关系。主语有原文依据。
- 无谓并列已经去重或拆句；独立信息、责任分工及明示数量的清单完整保留，普通行文末项按名词或动宾结构使用“和／或／以及／并”等连接。
- 主干延迟检查有实际位置依据；未凭主观语感全篇重写。
- 不把分析、待核项或修改说明混入正式文本；默认只交付审校全文。
